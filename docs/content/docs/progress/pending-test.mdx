# Pending Tests

The current release needs manual verification in these areas:

- Ark 视频与接入方式（[实现方案](/docs/progress/ark-video-api-plan)）：仅 Ark 渠道显示标准 API / Agent Plan。默认地址分别为 `/api/v3`、`/api/plan/v3`，切换方式保留自定义地址；保存、刷新和配置导入导出应保留接入方式。接入方式区域不提供独立的模型选择，图片、视频、文本和音频模型统一在下方“渠道模型”中获取或手动配置。Agent Plan 不过滤渠道中配置的视觉模型，已知 Seedance 套餐别名与标准 Model ID 均读取对应能力配置；已下线的 Seedance 1.5 Pro 应在提交前显示明确错误，不能继续请求 Agent Plan。自定义脚本仍优先。
- Ark 视频参数：视频页面、画布视频节点、配置节点均应跟随实际模型显示模式、分辨率、比例、时长和声音开关。2.0 可选 4K，fast/mini 无 1080p，1.0 支持 2 秒且不发声音字段；2.5 首尾帧只允许自适应，编辑需参考视频、自适应和智能时长。切换后无效值提示并阻止请求，不静默截断；首次选择可点击“使用模型默认值”。旧 OpenAI/Gemini 与调用脚本保持各自模式。
- Ark 视频素材与任务：文生、首帧、首尾帧和全模态参考采用明确角色，不按图片数量自动切模式；图片与音频支持本地素材，参考视频只接受公网 HTTP(S) / `asset://`，不可直接发送 `blob:`。视频页面可添加参考音视频；画布视频节点的远程参考来源与本地播放地址独立。测试图片/音视频数量、文件大小、已知元数据与总时长错误是否在提交前提示。2.0 仅音频拒绝，2.5 可仅音频。原生请求发送 JSON 到 `/contents/generations/tasks`，不得出现 OpenAI 的 multipart、`size` 或 `seconds`。
- Ark 视频恢复与保存：任务记录保存 `ark`、原渠道模型、创建地址及接入方式。刷新自动查询未结束任务；停止等待、未知状态、查询错误或等待窗口耗尽后可“继续查询原任务”，不能重新创建。切换模型/渠道地址不改变已有任务查询地址，删除原渠道应明确报错。成功结果优先保存浏览器本地；下载或本地存储失败需显示临时链接提示，支持下载。停止等待不会取消上游生成。需用本人有权限的标准 API 和 Agent Plan 账号分别验收；当前自动化验证使用模拟 HTTP，未发付费生成请求，未运行构建或类型检查。

- Ark 模型尺寸模板：`web/src/lib/image-model-config.ts` 集中维护模型名称匹配、分辨率、比例预设、默认值与像素范围；画布节点、配置节点、生图页面及请求层应使用同一模型配置。Seedream 5.0 pro 应提供 1K / 1.5K / 2K，5.0 lite 提供 2K / 3K / 4K，4.5 提供 2K / 4K，4.0 提供 1K / 2K / 4K；各比例使用官方文档的宽高值。仅指定比例时默认 2K（正方形为 2048×2048）；选择自动比例时保留所选分辨率，发送 `size: "2K"` / `"3K"` 等，由模型决定比例，完全自动时默认发送 `"2K"`。验证 lite 的 2K/16:9=2848×1600、3K/16:9=4096×2304、4K/16:9=5504×3040，以及 pro 的 1.5K。lite / 4.5 总像素为 3686400–16777216，4.0 为 921600–16777216，pro 为 921600–4624220，均支持 1:16–16:1；这些模型不再套用通用 16 倍数和最长边 3840 限制。自定义无效尺寸在面板和发送前均显示中文原因，不自动放大、裁剪或重试。切换模型后保留已填尺寸，超限时提示，重新选择分辨率应恢复新模型的比例预设和选中状态。文生图、参考图编辑、自定义脚本 `params.size`、保存刷新及弹窗摘要应保持一致；未知模型和 OpenAI/Gemini 的现有行为应保持正常。本项按 Ark 渠道中的模型名匹配，不包含 pro 图层拆分场景。
- Ark 渠道与生图：协议列表应并列显示 OpenAI、Gemini、Ark（火山方舟）。新建 Ark 渠道默认地址为 `https://ark.cn-beijing.volces.com/api/v3`，从已配置渠道切换时保留自定义地址（含 Agent Plan 的 `/api/plan/v3`）；保存、刷新及配置导入导出后仍保留 Ark 类型和生图参数。水印默认关闭，请求应携带顶层 `watermark: false`，开启后为 `true`；输出格式和提示词优化默认不传，手动选择后分别传 `output_format` 和 `optimize_prompt_options.mode`，按文档支持的模型验证。文生图和参考图编辑均以 JSON 请求 `/images/generations`，参考图放入 `image`，不发送 OpenAI 的 `n` / `quality`，多张生成沿用独立请求；JPEG 与 PNG 的 Base64 结果应使用正确 MIME。代理、取消、错误显示以及 OpenAI/Gemini 渠道应保持正常。自定义脚本仍优先，需自行处理额外参数；Ark 音频未内置适配时应提示配置调用脚本；视频能力见上方新增验收项。

## 图片分辨率尺寸表

选择分辨率和宽高比后，W/H 按下表填写，单位为像素。预设尺寸不受「16 倍数对齐」开关影响；该开关只控制手动输入尺寸时的对齐。最终生成尺寸以所选模型的实际输出为准。

| 宽高比 | 1K | 2K | 4K |
| --- | ---: | ---: | ---: |
| **1:1** | **1024 × 1024** | **2048 × 2048** | **2880 × 2880** |
| **2:3** | 1024 × 1536 | 1360 × 2048 | 2336 × 3520 |
| **3:2** | 1536 × 1024 | 2048 × 1360 | 3520 × 2336 |
| **4:3** | 1024 × 768 | 2048 × 1536 | 3312 × 2480 |
| **3:4** | 768 × 1024 | 1536 × 2048 | 2480 × 3312 |
| **16:9** | 1536 × 864 | 2048 × 1152 | **3840 × 2160** |
| **9:16** | 864 × 1536 | 1152 × 2048 | **2160 × 3840** |
| **21:9** | 2016 × 864 | 2688 × 1152 | **3840 × 1648** |
| **9:21** | 864 × 2016 | 1152 × 2688 | **1648 × 3840** |

待验收：

- 在画布和图像工作台逐项切换 3 档分辨率与 9 种比例，W/H 应与表格一致，重新打开设置后仍选中正确档位；重点检查 1K 的 2:3、16:9、21:9 及对应竖图，以及 4K 的 1:1。
- 所有 4K 预设提交时均不应触发本地总像素或最长边限制；生成和编辑请求、调用脚本应收到所选像素尺寸。
- 分辨率为自动时保留比例选择，比例为自动时禁用 W/H；手动输入 W/H 后，对齐开关仍应按原有方式工作。
- Gemini 在质量为自动时，应将表中尺寸识别为对应的 1K / 2K / 4K；显式选择质量时维持原有优先级。视频尺寸设置应保持原有行为。
